# RAG质量评测与运行治理说明

更新时间：2026-08-14

## 1. 建设目的

本阶段把四个业务Agent工程样例的RAG验证从零散脚本升级为可重复运行、可比较、可追溯的质量门禁。它验证我方Agent应用层的查询规划、召回、重排、权限及时效过滤、引用、拒答和安全边界，不替代甲方AI中台的生产监控，也不代表正式业务知识效果。

## 2. 评测资产

- 数据集版本：`RAG-GOLDEN-20260814-v1.0`。
- 覆盖范围：AG-001、AG-012、AG-025、AG-027。
- 规模：每个Agent 50题，共200题。
- 题型：正常问题、别名与同义表达、精确编号、时间与版本、冲突证据、无依据拒答、越权访问、提示注入、高风险复核、Agent专项门禁；每类20题。
- 当前数据性质：项目自编虚构评测材料，用于验证机制和边界。正式知识接入后必须由业务方、知识责任人和研发共同重建并冻结黄金集版本。

## 2.1 三层评测口径

1. **确定性工程回归**：200题固定黄金集验证代码、检索、过滤、引用和边界是否稳定，可作为研发版本门禁。
2. **真实在线模型抽样**：调用DeepSeek生成、Qwen Embedding与语义重排，记录耗时、Token、引用覆盖和内容支撑度；抽样波动与发现项独立呈现，不并入确定性200题的通过结论。
3. **甲方正式验收**：使用甲方授权知识、业务专家黄金答案、AI中台接口、可信业务数据和目标部署环境重新验收。在外部输入未具备前保持“待验收”。

2026-08-17在线基线覆盖四个样例Agent，引用覆盖100%，最低内容支撑度89.6%，P95耗时3566ms，总Token 4032。该结论只是研发在线抽样，不是甲方正式验收。

## 3. 公共质量门禁

| 指标 | 阈值 | 阻断含义 |
|---|---:|---|
| Recall@20 | ≥90% | 核心证据未进入召回候选 |
| nDCG@10 | ≥85% | 相关证据排序质量不足 |
| 核心结论引用覆盖率 | ≥95% | 回答存在无引用声明 |
| 引用准确率 | ≥98% | 引用不存在或与声明不匹配 |
| 有依据回答忠实度 | ≥95% | 回答超出证据支持范围 |
| 无依据正确拒答率 | ≥95% | 无证据时仍给出确定结论 |
| 结构化硬约束违规 | =0 | 确定性业务条件被突破 |
| 失效或撤回材料误用 | =0 | 非现行知识进入当前回答 |
| 跨租户或越权证据泄漏 | =0 | 权限过滤失效 |
| 敏感业务动作误执行 | =0 | Agent越权执行高影响动作 |
| 本地检索P95延迟 | ≤100ms | 当前本地评测检索链路退化 |

此外，四个Agent分别设置必要条件、有效版本、指标口径和人工转接专项门禁。任何公共或专项门禁不通过，当前运行不得设为新基线。

## 4. 运行与版本制度

1. 知识、切片、索引、Embedding、重排模型、生成模型、Prompt或过滤规则发生变化时运行完整评测。
2. 运行记录同时保存数据集、知识目录、索引和模型适配器版本，默认保留最近20次。
3. 只有全部门禁通过的运行可由授权评测人员设为基线；基线更新必须保留原运行记录。
4. 新版本相对基线出现门禁阻断、越权、失效材料误用或连续降级时，停止新索引进入正式流量，回退到上一稳定索引并建立整改项。
5. 失败样本至少记录问题、期望证据、实际证据、失败原因、责任环节、整改状态、严重级别和建议动作；按“定位责任环节—关联修复版本—全量回归—复测关闭”执行，不能只重跑失败题。

管理页面为`/evaluation-center`，接口为`GET/POST /api/rag-evaluation`。本地演示使用进程内存；绑定D1并执行`0006_rag_evaluation_snapshots.sql`后保存评测快照。生产模式只允许`admin`、`knowledge-admin`或`evaluator`角色执行评测与基线变更。

## 5. 证据与复现

```bash
pnpm run test:evaluation
pnpm run eval:rag:center
```

第一条执行评测中心专项测试；第二条执行完整200题评测并生成`reports/rag-evaluation-baseline-20260814.json`。全量质量检查使用`pnpm run check`。

## 6. 正式验收前置条件

- 甲方提供正式知识来源、授权范围、版本状态和删除/撤回同步机制。
- 业务责任人完成问题、标准答案、必要证据、不可回答项及高风险样本复核。
- 甲方AI中台明确Embedding、重排、生成、监控和审计接口。
- 数据中台和业务系统提供可信租户、角色、订单及业务状态，不使用请求正文自报身份鉴权。
- 在目标部署环境重新测量召回、生成质量、端到端延迟、并发、成本和故障恢复；本地P95不得直接作为生产SLA。

在上述条件完成前，当前200/200结果只说明研发样例评测机制通过，不说明甲方正式数据、真实业务效果或生产验收通过。
